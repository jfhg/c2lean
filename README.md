# c2lean — experimental Lean models of compiled C programs

`c2lean.py` translates C (via clang's LLVM IR) into Lean 4.
It implements a small fragment of LLVM IR (SSA, `icmp`/`br`/`phi`,
`alloca`/`load`/`store`/`gep`, calls, recursion, globals) plus a
fuel-bounded abstract machine that executes it.
In the C source code `//@` spec comments can be used to express propositions
about the Lean translation, e.g.
```
//@ requires validAt c:a c:n && c:n <= 8 && SumAt old c:a c:n < 4294967296;
//@ ensures  result == SumAt old c:a c:n;
```
Spec text is Lean: `c:name` refers to the C variable `name` (the model
keeps C names and spec-level names in separate scopes), `result` is the
return value, `m₀` the initial memory and `old` a shorthand for reading
words out of it.
The examples/ folder shows how this can be used in a Makefile to
verify the propositions against proofs provided in the Proofs/ folder.
Proofs need to be provided externally, they are not generated by c2lean.
Also note that c2lean does not guarantee memory safety.
It assumes memory safety in its execution model.

```
C source + //@ specs  ──c2lean.py──  Lean statements  ──kernel──  proofs
        make:   regen + lake build + axiom audit
```

## Using it

Install prerequisites, e.g. on Ubuntu:
```
sudo apt install clang elan python3-llvmlite
```
The Lean toolchain version is pinned in `lean-toolchain`; `elan`/`lake`
pick it up automatically.
```
cd examples
make                 translate every .c to Lean, build, print the axiom audit
make gen             only write the generated Lean (into build/)
make proofs          only regenerate the Proofs.lean aggregator
make clean           remove everything generated
```
The audit lists each spec: `AUDIT <name>` with the axioms its proof uses,
or `AUDIT-MISSING <name>` when no proof exists yet.

## Handing a spec to a prover

Three files suffice: `C2Lean/Semantics/Flat32.lean`, `C2Lean/SpecLib.lean`,
the generated program .lean file (`examples/build/C2Lean/Programs.lean`).
Then ask the prover to create a proof for the respective propositions.
(For anything with a loop the prover will also want `examples/Proofs/Reach.lean`,
which provides the step-indexed machinery for symbolic runs.)

## Known model boundaries

- Memory is total: unallocated reads return 0 (LLVM calls them poison);
  no `free`, no detection of C undefined behavior. Safety is a precondition of each spec.
- IR shapes are calibrated to clang 21.x (opaque pointers since 15);
  the frontend fails closed on anything it does not understand.
